## 1. 目标与原则

### 1.1 目标

把「按住说话 → 干净文字落光标」做成**日常可依赖**的自用工具：先稳住 Python P0，再迁 Tauri P1，最后补深度能力（词库 / 流式 / 选中改写）。

### 1.2 开发原则

1. **每阶段独立可用**：随时可停在当前阶段，不破坏已交付体验。
2. **先硬化再换壳**：不并行「大重构 + Tauri 重写」。
3. **失败不阻塞**：LLM / 云端 / 注入任一失败，链路仍有可感知兜底。
4. **用指标关门**：进入下一阶段前必须过对应 DoD，不以「感觉差不多」晋级。
5. **业余时间口径**：下表工期按业余碎片时间估算，可按实际投入伸缩。

### 4.3 P0.5 / P0 关门标准（DoD）

进入 **P1** 前必须全部满足：

- [ ] 记事本 / Chrome / VS Code：按住说话 → 文字落位，成功率可接受（目标 ≥98% 触发）
- [ ] 端到端延迟 P50 ≤ **5s**（PRD P0 口径；P1 再压到 ≤3s）
- [ ] 10 句口语样例 light 档 ≥ **80%** 无需手改
- [ ] 断 LLM 时仍输出原始转写
- [x] 剪贴板在正常注入后可恢复（或明确失败通知）
- [x] 托盘 mode / 关键热更新项重启后行为一致
- [x] `tech-design.md` 已提交
- [x] 代码已按模块边界拆分（或书面说明为何暂缓 + 接口草图）

**门禁口令：不过 DoD 不开 Tauri 工程。**

## 9. 优先级规则（排期时用）

遇到冲突时按此顺序取舍：

1. **不丢字 / 不脏剪贴板**（正确性）> 延迟优化 > 新 UI
2. **本地隐私链路** > 云端增强
3. **dogfood 阻塞项** > 文档与整洁度（但 tech-design 在进 P1 前为例外必做）
4. **单阶段做完再开下一阶段**；禁止「半成品 Tauri + 半拆 Python」长期并存无文档
