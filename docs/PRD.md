## 1. 概述 <a id="s1"></a>

### 1.1 产品定位（首屏文案，原文）

# Vowrite（述写）
> Speak to Write

Vowrite 是一款全局语音输入工具。按住快捷键口述，AI 将你的语音实时转为文字并自动润色，文字直接输出到当前光标位置，无需切换窗口。解放双手，让口述即书写。

> Vowrite is a global voice input tool. Hold the hotkey and speak, AI transcribes and polishes your speech in real time, text lands directly at your cursor anywhere. Speak to write.

### 1.2 一句话本质

**用 LLM 把 ASR 从"转写工具"升维成"表达工具"**——打通「语音 240 WPM → 键盘 60 WPM」之间 4 倍输入带宽差，并以"干净文字落光标"为终点的端到端体验产品。

### 1.3 项目性质与合规声明

- 本项目为**个人学习复刻项目**：以 Typeoff（Samywise LTD）为对标对象，基于其公开产品行为与更新日志做逆向分析与独立实现。
- **独立实现声明**：不使用 Typeoff 的任何代码、素材、文案、接口；所有实现基于公开可得的组件（whisper.cpp、Tauri、cpal 等）独立完成。
- 默认**自用 + 开源**，P0–P3 阶段不含商业化设施（账号、计费、支付）。

## 2. 背景与动机 <a id="s2"></a>

### 2.1 问题定义

- **物理瓶颈**：人类语音输出 ≈240 WPM，键盘输入 ≈60 WPM，存在约 4 倍带宽差；"脑子转得比手快"是文字工作者与程序员的日常损耗。
- **传统语音输入失败根因**：系统自带听写/输入法语音只做"转写"，输出含口水词、无标点、口语化，**不可直接发布**——用户仍需大量修正，有效产出速率被修正成本吞噬。
- **机会窗口**：ASR（Whisper 系）与 LLM 清洗能力均已商品化，"系统级 ASR × LLM 加工"的乘积体验在开源/自用侧存在空白。

### 2.2 对标产品分析结论（摘要）

Typeoff 逆向拆解结论（详见会话分析存档）：

1. 技术上**无黑科技**：ASR/LLM 均为租用或开源组件，本地引擎为 whisper.cpp 系，注入走"剪贴板 + 模拟粘贴"；
2. 真实壁垒在**脏活**：注入兼容性矩阵（微信/WPS/Zed 等逐 app 攻坚）、个人词库数据资产、中国本地化运营；
3. 产品哲学张力："忠实还原表达" vs "口语书面化"互相打架，格式化强度可调是收敛方案；
4. 对个人用户的真实价值场景：**对着 AI 编程工具口述 prompt、写 commit message、注释、文档、博客**——而非编写代码本体。

### 2.3 为什么现在做

- LLM 推理 API 成本进入分币级，本地 llama.cpp + 3060 6GB 显卡已可承载全离线链路；
- Tauri 2 已 GA，Rust 生态（cpal / whisper-rs / enigo / arboard）成熟，单人可维护；
- 本机环境齐备：Windows 11 + Python 3.12 + RTX 3060 Laptop 6GB + 本地 llama.cpp CUDA。

## 3. 目标用户与使用场景 <a id="s3"></a>

### 3.1 目标用户画像（P0–P3 唯一用户 = 自己，dogfooding 驱动）

- **身份**：中文为主的开发者/文字工作者；重度使用 AI 编程工具（Cursor / Claude Code / VS Code）；
- **环境**：居家/独立办公，Windows 11 主力机（RTX 3060 6GB），本地可跑推理；
- **痛点**：写周报、博客、commit message、给 AI 的长 prompt 时键盘输入速度远慢于思维组织速度。

### 3.2 核心使用场景（按优先级排序）

| # | 场景 | 说明 | 优先级 |
|---|---|---|---|
| S1 | 对 Cursor/Claude Code/VS Code 口述 prompt | 自然语言部分是真实效率杠杆 | P0 必须支持 |
| S2 | 口述 commit message / 注释 / 文档 | 短文本、高频 | P0 必须支持 |
| S3 | 写博客、周报、长文档（Obsidian/Typora/Word） | 长文本口述，需结构化润色 | P0 支持 |
| S4 | 微信/QQ/邮件消息回复 | 中短文本，注入兼容性要求最高 | P1 重点 |
| S5 | 中文口述 → 英文输出 | 跨语言（给英文社区写 issue/PR） | P2 |

### 3.3 明确不做的场景（边界）

- **代码本体编写**：精确符号、缩进、光标编辑不可语音化（Typeoff 同样如此）；
- **开放工位/公共场合**：语音输入社交成本无法用产品解决，不为其做设计；
- **多人会议转写/文件转录**：不是全局输入工具的职责，避免范围蔓延。

## 4. 功能需求 <a id="s4"></a>

需求分级：P0 = 核心链路验证；P1 = 产品化可用；P2 = 深度能力；P3 = 体验纵深；P4 = 待决策。

### 4.1 P0 — 核心链路（Python CLI 原型）

| 编号 | 功能 | 需求描述 | 验收要点 |
|---|---|---|---|
| F01 | 全局按住触发 | 按住**右 Ctrl** 开口说话，松开结束；全局生效，不依赖前台窗口 | 任意应用前台按住即触发，不串按键 |
| F02 | 音频采集 | 16kHz 单声道采集，最短 0.4s 有效时长过滤（防误触），最长 120s 上限保护 | 静默误触不进入转写 |
| F03 | ASR 转写 | 本地 faster-whisper（whisper.cpp 同源）默认；OpenAI 兼容转写 API 可选；中文优先 | 中文短句字错误率肉眼可接受 |
| F04 | LLM 润色 | OpenAI 兼容 /v1/chat/completions；默认指向本地 llama.cpp server；两档强度：**light**（仅清口水词/标点/错字，忠实原意）/ **heavy**（可书面化改写）；LLM 不可用时**自动降级输出原始转写** | light 档不改语气；失败不阻塞输出 |
| F05 | 文字注入 | 写剪贴板 → 模拟 Ctrl+V；焦点检测（可编辑区域判断），不可靠时盲贴兜底；注入失败兜底：文字留在剪贴板并提示 | 记事本/Chrome/VS Code 三处注入成功 |
| F06 | 状态可见 | 控制台输出录音/转写/润色/注入各阶段状态与耗时 | 各阶段耗时可见（延迟埋点） |
| F20 | 对话模式 | mode=chat：口述问题，AI 答案直接落光标；与 polish（转写润色替代打字）可配置/命令行切换。对齐 Typeoff「随便问」能力的简化变体（大王 2026-10-29 实测反馈新增，P0 已实现） | 同一输入两模式输出分化：polish 保留原话、chat 给出答案 |
| F21 | GUI 常驻壳 | 托盘常驻（pystray）+ 右键菜单（监听开关/模式切换/LLM 服务启停/设置/自检）+ 设置窗（配置读写、热更新、重启引擎）+ llama-server 进程托管（自动拉起/就绪探测/仅管理自有进程）+ 开机自启（HKCU Run）+ 单实例锁。提前实现 P1 F09/F11 部分能力（大王 2026-10-29 反馈：命令行操作不便） | 双击 `p0/start_vowrite.bat` 常驻托盘；设置保存后热项立即生效；托管启停生命周期可验证 |

### 4.2 P1 — 产品化（Tauri 2 桌面版）

| 编号 | 功能 | 需求描述 |
|---|---|---|
| F07 | 悬浮指示器 | 屏幕底部 always-on-top 小窗：录音波形/状态动画，视觉不抢焦点 |
| F08 | 历史记录 | SQLite 本地存储转写历史：按日期分组、搜索、一键复制、重新润色 |
| F09 | 设置界面 | 触发键、引擎、润色强度、语言等可视化配置 |
| F10 | 可配置触发键 | 右 Ctrl 之外支持 F 区键、鼠标侧键等自定义（借鉴 Typeoff v1.0.34 的退路设计） |
| F11 | 开机自启 + 托盘 | 后台常驻、托盘菜单快捷开关 |

### 4.3 P2 — 深度能力

| 编号 | 功能 | 需求描述 |
|---|---|---|
| F12 | 双引擎自动回退 | 云端转写失败/超时自动切本地 whisper；本地模型可下载可删除（Typeoff v1.0.51/57 同款策略） |
| F13 | 个人词库 | 专业术语、人名、品牌词条（SQLite），注入 LLM prompt 约束识别 |
| F14 | 修正学习 | 对比用户修正文本与原转写，自动挖掘候选词条建议入库（Typeoff v1.0.64 思路） |
| F15 | 润色强度设置 | light / heavy / off 三档，对应 prompt 参数化（Typeoff v1.0.52 思路） |
| F16 | 跨语言输出 | 中文口述 → 英文输出（先保证 S5 场景，60+ 语言后置） |

### 4.4 P3 — 体验纵深

| 编号 | 功能 | 需求描述 |
|---|---|---|
| F17 | 流式实时预览 | 说话过程中实时显示部分转写，感知延迟提前到说话瞬间（体验分水岭） |
| F18 | 随便问/选中改写 | 选中文字（模拟 Ctrl+C）→ 口述指令 → LLM 改写回写 |
| F19 | 使用统计 | 每周字数/次数统计页（自我反馈用，非成就系统） |

### 4.5 P4 — 待决策项（默认不做）

macOS 支持、iOS/Android 键盘扩展、账号计费商业化、多语言 UI。**进入 P4 前需重新决策**（见 §11）。

## 5. 非功能需求 <a id="s5"></a>

| 维度 | 指标 | 备注 |
|---|---|---|
| 端到端延迟 | 松手 → 文字落位 ≤ **3s**（P1 目标）；P3 流式后感知延迟 ≈ 0 | 每阶段埋点计量：ASR 尾包 ≤1s，LLM ≤2s，注入 ≤50ms |
| 隐私 | **本地模式音频不出设备**（零上传）——强于对标产品免费版；云端模式仅传输必要音频 | 自用版无计费需求，可承诺比 Typeoff 更彻底的本地性 |
| 可靠性 | 单点失败不阻塞链路：LLM 失败→输出原转写；云端失败→回退本地；注入失败→保留剪贴板并提示 | 对齐 Typeoff 血泪日志教训 |
| 兼容性 | P1 验收矩阵：记事本、Chrome、VS Code、微信、Word 五处注入成功率 100% | 兼容矩阵按真实使用反馈滚动扩张 |
| 资源占用 | 常驻内存 ≤500MB；本地推理显存 ≤4GB（3060 6GB 需与其他 GPU 任务共存） | 本地模型默认 small/medium 档，large-v3-turbo 可选 |
| 成本 | 本地路线 0 元/月；云端 API 路线 ≤¥30/月（每天 30 分钟语音量） | 模型下载支持 hf-mirror 镜像（国内网络） |
| 数据安全 | 历史与词库明文 SQLite 存于本机用户目录，无任何遥测上报 | 自用信任模型，不引入账号体系 |

## 6. 竞品对标与差异化 <a id="s6"></a>

| 维度 | Vowrite | Typeoff | Wispr Flow | 讯飞输入法（PC） | 系统听写 |
|---|---|---|---|---|---|
| LLM 润色 | ✅ 本地/云可切 | ✅ 云端 | ✅ 云端 | ❌ | ❌ |
| 本地离线转写 | ✅ 默认 | ✅ | ❌ | ❌ | 部分 |
| 音频不出设备 | ✅ 可全链路 | ⚠️ 仅本地模式 | ❌ | ❌ | ⚠️ |
| 免登录 | ✅ | ❌ 强制登录 | ❌ | ⚠️ | ✅ |
| 中文优化 | ✅ 主战场 | ✅ | 一般 | ✅ 识别最强 | 一般 |
| 开源可审计 | ✅ | ❌ | ❌ | ❌ | ❌ |
| 价格 | 0 元（自部署） | ¥379/年 | $144/年 | 免费 | 免费 |

**差异化主张**：不是做"更便宜的 Typeoff"，而是做"**全离线、免登录、可审计的个人版语音表达工具**"——隐私彻底性、可改性、零成本是商业产品结构性给不了的三件事。

## 7. 技术架构概要 <a id="s7"></a>

> 详细设计另立 `docs/tech-design.md`（P0 完成后补），此处仅锁定架构方向，防止实现漂移。

### 7.1 技术路线决策（当前假设，可被推翻）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 桌面框架 | **Tauri 2 + Vue3** | 团队既有栈（Lunark/ai-girlfriend 经验）；Rust 单语言统一整条管线；包体小 |
| 原型验证 | **Python CLI（P0）** | 1–2 天验证核心体验值不值得投入，再上工程 |
| ASR | 本地 faster-whisper/whisper.cpp（CUDA）优先，云 API 可选 | 3060 6GB 可承载；隐私彻底；hf-mirror 下载 |
| LLM 润色 | OpenAI 兼容接口，默认本地 llama.cpp server | 既有 D:\AI\llama.cpp 环境；可随时切云端 |
| 注入 | 剪贴板 + 模拟 Ctrl+V 为主，焦点检测为辅 | Typeoff 验证过的最稳路线（v1.0.1 即此方案，AX 直插已放弃） |
| 存储 | SQLite | 历史/词库/配置，单文件 |

### 7.2 管线数据流

```
按住右Ctrl ─→ 采集(16k mono) ─→ VAD分段 ─→ ASR(云端WS ⇄ 本地whisper自动回退)
                                                       │
              悬浮指示器(UI) ←─ 状态事件 ──────────────┤
                                                       ↓
光标落位 ←─ 注入(剪贴板+模拟粘贴) ←─ LLM润色(强度/词库约束) ←─ 原始转写
```

## 10. 风险与应对 <a id="s10"></a>

| # | 风险 | 等级 | 应对 |

## 11. 开放问题（待决策） <a id="s11"></a>

| # | 问题 | 当前默认 | 决策时点 |
|---|---|---|---|
| Q1 | 是否商业化（账号/计费/多用户） | 否，P0–P3 纯自用 | P4 之前 |
